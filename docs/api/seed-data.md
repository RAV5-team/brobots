# Демо-данные сервиса api

Данные лежат в `services/api/internal/seed/data/` и встроены в бинарь. Загрузка — `api seed` или переменная `SEED_DEMO=true` при старте. Повторная загрузка ничего не перезаписывает: справочники и определения параметров обновляются, а классы, решения, процессы и демо-локации создаются, только если их ещё нет (по коду или названию). Правки администратора в демо-данных сохраняются.

Процессы, локации, задачи и проекты загружаются через тот же сервисный слой, что и запросы API, поэтому проходят те же проверки.

## Файлы и источники

| Файл | Что внутри | Источник |
|---|---|---|
| `reference.yaml` | типы объектов, 9 отраслей, способы обработки, виды работ, классы OP-01…OP-10, 6 источников данных | Figma A6, A8; PRD 6 |
| `catalog_export_v4.csv` | 223 строки каталога организатора, без изменений | `Датасет/catalog_export_v4.csv` |
| `robots.yaml` | ТТХ и классы 20 демо-роботов, значки PDF-каталога, подсказки классов по сценарию | «Примеры решений» (docx), лист «Каталог» экономической модели v1.1, Figma A1 |
| `startup_items.yaml` | 29 позиций для запуска: инфраструктура, ПО, внедрение, поддержка | экран «Каталог» (PRD 13.5), оценка команды |
| `parameters.csv` | 132 параметра трёх типов объектов с единицами, диапазонами, подсказками | `Датасеты_хакатон.xlsx`, скрипт `scripts/extract_datasets.py` |
| `processes.yaml` | 12 процессов справочника со значениями по умолчанию и формулами | Figma 07, 09а; экономическая модель, блок 2 |
| `demo.yaml` | 4 демо-локации, 15 задач, 3 проекта с подбором и расчётом кандидатов (`evaluate`; если калькулятор недоступен — только подбор, в журнале предупреждение) | датасеты организатора, Figma 12, 15а |

Пересобрать `parameters.csv` после обновления датасета:

```bash
python scripts/extract_datasets.py path/to/Датасеты_хакатон.xlsx
```

## Импорт каталога

- 223 строки склеиваются в 187 решений по `id`; отрасли и сценарии объединяются в списки.
- Разные цены одного продукта становятся альтернативными предложениями, первая — по умолчанию (Доп. 6). Цены — с НДС, без доставки, пусконаладки и интеграции.
- Цена «2 700 000,00» разбирается в число; кавычки в названиях компаний заменяются на «»; подтипы нормализуются («Робот уборщик» → «Робот-уборщик»); опечатка «Доставка биоматериаловм» исправляется.
- Грузоподъёмность из названия («грузоподъемность до 1 500 кг») переносится в ТТХ с пометкой источника.
- Класс операции подсказывается по сценарию только при однозначном соответствии: уборка помещений и улиц → OP-07, инвентаризация склада → OP-06, доставка биоматериалов → OP-08, патрулирование → OP-09, сортировка грузов → OP-03, сборка товаров → OP-02. Источник строки подписан «Подсказка по сценарию организатора — проверить».
- PuduBot 2 из примеров организатора добавлен как отдельное решение без цены: на нём видна проверка `price`.

Итого в каталоге 217 позиций: 187 решений организатора, PuduBot 2 и 29 позиций для запуска.

## Допущения демо-данных

- ТТХ части роботов взяты по аналогам и помечены `specsConfirmed: partial` или `no` с текстом источника: AK-2000-2 по DMR Carrier P, AMR 800 по AMR 1500, Ronavi M по Ronavi H1500. Для DMR Carrier P время зарядки, температуры и мощность — допущения экономической модели.
- Производительность-диапазон («40–60 паллет/ч», «80–100 паллет/ч») — в расчёт идёт нижняя граница, диапазон хранится.
- Базовые значения датасетов записаны в демо-локации с источником `organizer`; отдельные значения помечены допущениями (`assumptions` в `demo.yaml`).
- Даркстор Юг: площадь 10 500 м² вместо 8 400 м² из макета — минимум датасета 10 000 м²; приёмка и отгрузка по 500 паллет (минимум датасета), объём задачи 620 паллет/сут задан в самой задаче.
- Упаковка на РЦ Химки: 833 заказа/сут из макета введены как значение пользователя; оклада операторов упаковки в датасете нет, поэтому готовность задачи 8/9.
- Позиции для запуска — данные команды со статусом `estimate` и источником «Позиции для запуска · оценка команды RAV5».
- Формулы процессов ссылаются на коды параметров (`wh_…`, `ap_…`, `med_…`) или роли (`shifts_per_day`, `active_area`, `min_aisle_width`). Если на локации нет нужного значения, берётся значение процесса с пометкой в `provenance.note`.
