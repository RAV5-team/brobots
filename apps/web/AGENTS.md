# Правила фронтенда (RAV5 / TWIG AI)

## Стек
- React + TypeScript (strict) + Tailwind. <!-- замените на свой стек -->
- Токены: `apps/web/src/styles/tokens.css` (CSS-переменные) → алиасы в теме Tailwind. Хардкод hex/px в компонентах запрещён.
- Шкала отступов и размеров — в пикселях: p-4 = 4px, p-16 = 16px (не как в стандартном Tailwind). Цвета, тени, радиусы, шрифты Tailwind по умолчанию отключены — только токены.
- Текст — только через type-* (`apps/web/src/styles/typography.css`).
- Примитивы UI: `apps/web/src/components/ui/*`. Каркас приложения (sidebar, layout): `apps/web/src/components/shell/*`.
- Иконки: одна библиотека (lucide-react). Текстовые символы «→», «+», «⌄» из макета заменяются иконками.

## Источник дизайна
- Figma-файл: `sd1kJRdpW6RBFzSi1ztXYK`. Карта экранов и node-id: `apps/web/docs/design/screens.md`.
- **Никогда не запрашивай секцию `15935:2` целиком** (25 экранов, ~7300 слоёв). Только конкретный экран или его часть.
- В макете нет компонентов и variables. Источник правды для токенов и компонентов — этот репозиторий:
  `apps/web/docs/design/tokens.md`, `apps/web/docs/design/components.md`, `apps/web/docs/design/decisions.md`.
- Экономь вызовы Figma MCP: сначала проверь `apps/web/.figma-cache/<nodeId>/`, результаты сохраняй туда же.
- Файл — рабочий файл дизайнера. Ничего в него не записывать: `use_figma` — только read-only скрипты; `generate_figma_design`, `add_code_connect_map`, `send_code_connect_mappings`, `create_new_file`, `upload_assets` — запрещены без явного разрешения пользователя.
- Кэш `.figma-cache/<nodeId>/` устаревает, когда дизайнер меняет экран. Если пользователь говорит, что экран обновлён, — удали его папку в кэше и запроси заново.

## Порядок работы с экраном
Используй скилл `figma-screen`. Кратко: screenshot → design context (для экранов выше ~2000 px — по секциям через get_metadata) → сопоставление с токенами и компонентами → код → визуальная сверка на 1366 px.

## Компоненты
- Перед созданием элемента ищи существующий в `apps/web/src/components/ui` и `apps/web/docs/design/components.md`.
- Если нужного примитива нет — не верстай его инлайн в экране. Остановись, добавь его в `apps/web/docs/design/components.md`, реализуй в `apps/web/src/components/ui/`, затем продолжай.
- Каждый новый примитив: типизированные props, все варианты из инвентаря, состояния hover / focus-visible / disabled.

## Решения вместо дизайнера
- Всё, чего нет в макете (состояния, адаптив, выбор между расходящимися вариантами), решай по `apps/web/docs/design/decisions.md`.
- Нет решения — предложи вариант, запиши его в apps/web/docs/design/decisions.md со статусом `proposed` и сообщи в отчёте.

## Визуальная проверка
- Инструмент — Playwright MCP. Просить у пользователя скриншоты нельзя; если MCP недоступен — остановись и сообщи.
- Dev-сервер: скрипт dev в apps/web (менеджер пакетов репозитория), адрес http://localhost:5173. Запускай в фоне, если не запущен; не останавливай между шагами.
- Роль в dev-сборке задаётся параметром `?as=guest|user|admin` без экрана входа. Параметр работает только в dev-режиме без Keycloak (`VITE_OIDC_URL` пуст); с Keycloak и в любой сборке роль — только из токена, нет токена — гость (D-112).
- Размер окна — 1366×768 (browser_resize). Для экранов выше 768 px — скриншот всей страницы.
- Перед скриншотом дождись загрузки шрифтов и сети.
- Скриншот реализации — apps/web/.figma-cache/<nodeId>/impl-1366.png, рядом со screenshot.png из Figma.
- Кроме скриншота, проверь через browser_evaluate вычисленные стили ключевых элементов (отступы, размер и начертание шрифта, цвета) против токенов.
- Консоль браузера — без ошибок.

## Definition of done
- typecheck, lint, тесты — зелёные; `npm run test:e2e` и `npm run test:visual` — тоже.
- JS первой загрузки — не больше 300 КБ gzip (временно 305 — до слияния потоков шагов 1–3, D-109): `npm run check:bundle`. Служебные страницы `/dev/*` и тяжёлые фикстуры — ленивой загрузкой.
- Новый готовый экран — строка в файле своего раздела `e2e/screens/<раздел>.ts` (`app`, `projects`, `params`, `matching`, `simulation`, `economics`): маршрут и роли в `routes`, эталон в `visual`, открытый слой для axe в `layers`. `e2e/readyScreens.ts` только собирает разделы.
- Эталоны (`e2e/__screenshots__`) обновляются только осознанно — `npm run test:visual:update` (Docker, образ Playwright той же версии), причина — в сообщении коммита. Правка общих компонентов обратно совместима: эталоны готовых экранов не меняются.
- Скриншот реализации на 1366 px сверен со скриншотом Figma; оставшиеся отличия перечислены с причинами.
- Нет хардкода цветов, шрифтов, радиусов; нет дублей примитивов.
