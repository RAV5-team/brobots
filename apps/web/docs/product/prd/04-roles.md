# 4. Роли и права

Обязательных ролей три: гость, зарегистрированный пользователь и администратор. Роль вендора — дополнительная функция, не обязательная \[ТЗ 3.1.1\].

| **Роль** | **Что может** | **Ограничения** | **Источник** |
|----|----|----|----|
| Гость | Смотрит каталог. Выбирает тип объекта. Выполняет демонстрационный расчёт на данных организатора | Коммерчески чувствительные данные не сохраняются | \[ТЗ 2.1.1, 3.1.2\] |
| Зарегистрированный пользователь | Создаёт, редактирует, копирует, сохраняет и удаляет проекты. Вводит параметры вручную или из файла. Получает подборку и сравнивает варианты. Сравнивает не менее трёх сценариев в одном проекте. Запускает имитацию. Выгружает результаты | Видит только свои проекты | \[ТЗ 2.1.2–2.1.5, 3.1.3, 4.4.3\] |
| Администратор | Ведёт каталог: добавляет и редактирует решения. Управляет справочниками, параметрами по умолчанию, источниками данных и расчётными нормативами. Запускает обновление каталога по запросу | — | \[ТЗ 2.1.6, 3.1.4, 3.3.5, 3.3.6\] |
| Вендор | Состав функций в ТЗ не описан | Реализуется по желанию команды | \[ТЗ 3.1.1\] |

- Единственное, чего нет у гостя, — свои локации и сохранение результатов. Весь расчётный путь, включая выгрузку, гостю доступен: это прямо отвечает требованию показать полный сценарий без регистрации \[ТЗ 3.1.2\].

- Демонстрационные учётные записи для ролей пользователя и администратора — требование финальной сдачи \[ТЗ 8.2.5\]; на экране они подставляются в один клик.

- Пара «пользователь / администратор» совпадает с двумя персонами макетов: «И. Демидов · рабочий кабинет» и «А. Соколова · администратор · каталог и нормативы» \[Экран 06, А1\].

> **Пароли демо-доступа напечатаны на публичном экране входа. Для конкурсной демонстрации это удобно, для любой другой среды — нет. Плашки должны быть видны только в демо-сборке. Расхождение — раздел 15.**

**Требования к проектам пользователя**

- Проект можно открыть повторно и воспроизвести ранее выполненный расчёт. Сохранённая оценка при этом открывается только для просмотра, а правка идёт через новый проект на её основе (раздел 11.1). При этом указывается версия исходных данных и версия расчётной модели \[ТЗ 3.1.5\].

- Удаление проекта удаляет и связанные с ним загруженные файлы \[ТЗ 4.4.6\].

- Ошибка загрузки данных не должна приводить к потере ранее сохранённого проекта \[ТЗ 4.3.4\].

**Требования к доступу и безопасности**

- Разграничение доступа по ролям \[ТЗ 4.4.1\].

- Пароли не хранятся в открытом виде \[ТЗ 4.4.2\].

- Проекты разных пользователей изолированы \[ТЗ 4.4.3\].

- При размещении в сети данные передаются по защищённому протоколу \[ТЗ 4.4.4\].

- К финальной сдаче нужны демонстрационные учётные записи для ролей пользователя и администратора, если есть авторизация \[ТЗ 8.2.5\].

**Решение по персонам.** Основная — ответственный за внедрение на предприятии (в макетах И. Демидов, рабочий кабинет); вторая — вендор или продажник. В прототипе v2 показана только первая.

**Открыто**

- Что именно считается «коммерчески чувствительными данными» для гостя — в ТЗ не раскрыто \[ТЗ 3.1.2\].

- Делаем ли роль вендора к финалу.
