# 10. Локации

Локация — конкретная площадка: склад, аэропорт, медучреждение. Она даёт условия и ограничения, с которыми сверяются ТТХ роботов, и данные для экономики: режим работы, персонал, зарплаты \[ТЗ 3.2.1\]. В локацию добавляются процессы из библиотеки. Из локации создаётся проект.

## 10.4. Процессы в локации

Вкладка отвечает на вопрос «что реально происходит на площадке сейчас» — без привязки к роботам. Процесс попадает сюда копией шаблона из справочника и дальше живёт своей жизнью.

Подпись блока: «Процессы объекта · 5 процессов описано» и «Что реально происходит на площадке сейчас — без привязки к роботам» \[Экран 15а\].

**Особенности данных, которые влияют на формы и валидацию**

- Часть полей текстовая и без диапазона: тип покрытия, тип стеллажной системы, габариты в формате Д×Ш×В, WMS, ERP/1С, тип учреждения, режимы работы \[ДС\].

- У трёх полей склада min равен max: рабочих дней в году 365, коэффициент начислений 1,302, наличие WMS «Да». В датасете это константы \[ДС-Склад\].

- Часть значений производная. Пример: среднесуточные пассажиры = годовой поток / 365 \[ДС-Аэропорт\].

- Расхождение в датасете медучреждения: примечание даёт формулу «порций = коек × занятость × кратность». При 650 койках, занятости 82% и 3 кормлениях это 1 599, а базовое значение — 1 950, то есть без учёта занятости \[ДС-Мед\].

- Единица у «Количество паллетомест» записана как «м/п» \[ДС-Склад\].

| **N** | Группы исполнителей | Список через «;» с листа «Локация» | Да | Каждая группа есть в профиле локации и у неё заполнен оклад | Операторы погрузчиков |
| **O** | Доля времени на процесс, % | Список чисел через «;» в порядке колонки N | Да | 0–100 для каждой группы; число значений совпадает с N | 100 |
| **P** | Операторов флота на смену | Целое | Нет | ≥ 0; пусто — из шаблона | 1 |
| **Q** | Источник данных | Текст | Нет | — | Демо-датасет организатора |
| **R** | Комментарий | Текст | Нет | — | — |

- Колонки N и O читаются парами: «Операторы погрузчиков;Отборщики» и «100;30» означают две группы с долями 100% и 30%.

- Процесс без группы с заполненным окладом загрузится, но получит статус «не хватает: исполнители, оклад» и в расчёт экономии ФОТ не войдёт — так же, как уборка и инвентаризация на демо-локации \[Экран 15а\].

- Колонки C и D только для чтения: класс наследуется из шаблона и на локации не меняется \[Экран 16\].

**Что из этого следует для расчёта**

- Число роботов считается от пиковой потребности в операциях \[ТЗ 3.5.2\]. Пик по складу задан коэффициентом 1,5 к среднечасовой нагрузке; по аэропорту — пиковыми рейсами и пассажирами в час; по медучреждению — окнами 07:00–10:00 и 15:00–17:00 \[ДС\].

- Экономия ФОТ входит в обязательные показатели \[ТЗ 3.5.2\]. Коэффициент начислений на ФОТ во всех трёх датасетах — 1,302 \[ДС-Легенда\].

- Для склада организатор задаёт коэффициент потерь рабочего времени 25%: потребная численность на 25% выше нормативной \[ДС-Склад\].

- Неполная автоматизация есть в самих данных: негабарит, упаковка, функция пищеблока помечены как частично или полностью ручные.

**Связь с каталогом**

- В файле каталога процессу соответствует поле «Сценарий». Значения, близкие к трём типам объектов: внутрискладская логистика, сортировка грузов, уборка помещений, инвентаризация склада, перевозка грузов на закрытых площадках, доставка биоматериалов \[Кат-CSV\].

- Справочник типов решений с типовыми задачами дан организатором: AMR, FMR, робот-штабелёр, робот-тягач, робот-уборщик, беспилотный погрузчик, стационарные системы хранения \[Доп. 8\].

- Соответствие «процесс датасета → сценарий каталога → тип решения» организатор не даёт. Его строит команда.

**Открыто**

- Как RAV5 собирает задачи: список процессов, объём, текущая стоимость, доля, которая остаётся людям. Нужны прототипы и логика команды.

- Таблица соответствия процессов, сценариев каталога и типов решений.

- Чем закрываем «нет данных»: выработка погрузчиков, объём и з/п упаковки, уборка склада.

Для локации флоу отрисован в Figma: форма «Новая локация» после загрузки файла \[Экран «Локации · новая локация · из Excel»\] и окно «Сопоставить параметр» \[Экран «Локации · новая локация · сопоставить параметр»\]. Для процесса 09а и робота А2 экранов нет: логика та же, листы и справочник полей свои. ТЗ требует загрузку по шаблону и проверку типов, единиц, обязательных полей и диапазонов \[ТЗ 3.2.3, 3.2.4\].

Форма после загрузки

Окно «Сопоставить параметр»

Кнопки «Пропустить строку» и «Применить».

- Значения подставляются в форму сразу; ошибки исправляются в полях формы, а не в файле. Сохранение локации — обычной кнопкой формы.

- В файле из макета три листа: «Локация», «Персонал», «Процессы». Шаблон 10.6 устроен иначе: «Инструкция · Локация · Процессы в локации · Процессы». Привести шаблон к файлу из макета — отдельный лист «Персонал» удобнее строк в листе «Локация» (расхождение 133).

- Пол и Wi-Fi приходят строками листа «Локация» с кодами из 10.6. Неизвестная единица, например «кг/м²» вместо «т/м²», попадает в счётчик «не распознаны» и открывает «Сопоставить».

Правила

- Диапазоны и единицы берутся из справочника параметров объекта (раздел 10.5 и Приложение А; для параметров площадки — колонка «Проверка» в 10.6); правило одно для формы и для файла \[ТЗ 3.2.4\].

- Дубли параметров в файле — берётся последняя строка, в сводке об этом сказано.

- Ошибка чтения файла (не тот формат, повреждён) не трогает уже сохранённую локацию и проект \[ТЗ 4.3.4\].

- Для процесса и робота отличается только лист и справочник полей: «Процессы» (раздел 9.5) и «Решения» + «Операции робота» (раздел 6.4).
