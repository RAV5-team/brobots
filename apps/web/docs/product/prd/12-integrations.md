# 12. Интеграции

Раздел «Интеграции» есть в меню \[Экран «Дашборд»\], экран отрисован в Figma (12.1). В конкурсной версии интеграции с промышленными системами и госсервисами не обязательны, но архитектура должна предусматривать API, а возможные интеграции нужно описать \[ТЗ 3.8.1, 3.8.3\].

**Требования ТЗ**

| **Требование** | **Источник** |
|----|----|
| Данные поступают из файлов и встроенной базы; архитектура предусматривает подключение API | \[ТЗ 3.8.1\] |
| Программные интерфейсы импорта данных об объектах, каталоге и расчётных нормативах | \[ТЗ 3.8.2\] |
| Описание интеграций с WMS, ERP, 1С, системами мониторинга оборудования и аналитикой ФЦ БАС | \[ТЗ 3.8.3\] |
| Проверка продукции по государственным реестрам и расчёт мер господдержки — дополнительная функция | \[ТЗ 3.8.4\] |
| Все реализованные API документированы; рекомендуется OpenAPI | \[ТЗ 3.8.5, 4.2.5\] |
| Интеграционные API — дополнительное преимущество у жюри | \[ТЗ 9\] |

**Системы, которые названы в данных организатора**

| **Система** | **Где упомянута** | **Зачем интеграция** | **Что даёт платформе** |
|----|----|----|----|
| WMS | «Наличие WMS обязательно для роботизации» \[ДС-Склад\] | Объёмы операций, SKU, задания роботам | Автозаполнение объёмов процессов |
| ERP / 1С | «Интеграция через REST API или COM-коннектор» \[ДС-Склад\] | Персонал, зарплаты, затраты | Автозаполнение затрат на персонал |
| FIDS / AODB | «Источник данных для расписания роботов» \[ДС-Аэропорт\] | Рейсы и расписание | Пиковая нагрузка аэропорта |

| СКУД | «AMR должны интегрироваться со СКУД для прохода через двери» \[ДС-Аэропорт\] | Проход роботов по зонам | Ограничение маршрутов |
| МИС (ЕМИАС) | «Источник данных для планирования маршрутов» \[ДС-Мед\] | Заявки отделений | Объёмы процессов медучреждения |
| ЛИС | «Для автоматического формирования заявок на доставку проб» \[ДС-Мед\] | Заявки на доставку проб | Объём процесса «Доставка · пробы» |
