# Контракт API для фронтенда: вопросы бэкенду

Типы ответов генерируются из контрактов (`npm run gen:api` → `src/api/generated/`): `packages/contracts/openapi/api.yaml` (services/api) и `services/simulation/docs/openapi.json`. Ответы переводятся в модель экрана мапперами `src/api/mappers/*` с проверкой обязательных полей (`ContractError`). Пока сервисы — моки на фикстурах в форме этих ответов; чего в API нет, мок хранит рядом и помечает.

Статусы: `open` — ждём ответа; `answered` — ответ получен, фронт обновлён.

| № | Вопрос | Почему важно | Что сейчас на фронте | Статус |
|---|---|---|---|---|
| 1 | **Обязательные поля в `api.yaml`.** Ни у одной схемы нет `required`: у `Project`, `Evaluation`, `CalcResult` все поля необязательные. Можно добавить теги обязательности в Go-структуры (swaggest/openapi-go читает `required:"true"`)? | Сгенерированные типы — сплошь `?:`; без `required` фронт не отличает «поле обязательно, но не пришло» от «поля может не быть» | Мапперы проверяют сами (`required()` в `src/api/contract.ts`) — список обязательных полей живёт на фронте и может разойтись с бэкендом | open |
| 2 | **Отдельный эндпоинт итога и экономики?** Сейчас итог шага 4 (PRD 11.5) собирается из `Evaluation`: сценарии «покупка» и RaaS — `CalcResult` выбранного решения, база — `details.baselineOpexYearRub`. Устойчивости ±20 % и реестра условий в API нет | Шаг 4 и отчёт 09 показывают блоки, которых нет в ответе | `getEconomics` в моке строит итог из формы `Evaluation`; устойчивость и реестр — фикстура в форме экрана (`projectEconomics.ts`). Денежный поток и стоимость операции считаются на фронте | open |
| 3 | **Правило «что устаревает» (D-89, proposed).** В PRD его нет. Фронт: допущения шага 1 и «Параметры расчёта» → подбор и прогон устарели; смена варианта подбора → прогон устарел, состав и план сбрасываются; состав и условия симуляции → прогон устарел; новый прогон снимает пометку. Совпадает ли с `Evaluation.stale` и логикой бэкенда? | Иначе экран покажет «актуально», а бэкенд — «нужен пересчёт» (или наоборот) | `applyInputsPatch` в `src/domain/projectInputsRules.ts` | open |
| 4 | **Где хранятся решения по шагам.** В `Project` нет: шага черновика («остановились на»), уточнённых допущений шага 1, «Параметров расчёта», состояния симуляции (состав, условия, прогон, план, «принять риск»), выбранного сценария итога. `PATCH /projects/{id}` принимает только `name` и `horizonYears` | Черновик должен открываться на своём шаге с введёнными данными (PRD 11.1, автосохранение D-21) | Мок хранит это рядом с проектом (`PROJECT_LOCAL_STATE`, тип `ProjectLocalState` в `src/api/mappers/project.ts`) | open |
| 5 | **Снимок результата в списке проектов.** Список A1 и дашборд показывают CAPEX, OPEX, окупаемость и эффект сохранённой оценки (D-81). В `Project` чисел нет, только `latestEvaluation` и `selection.calcResultId` | Без чисел в списке — N+1 запрос `evaluation` на каждую строку | Мок хранит снимок в состоянии проекта; тест сверяет его с выбранным `CalcResult` (одни числа везде) | open |
| 6 | **Формат трасс для 2D-плеера.** `GET /api/simulations/{id}/traces` в `openapi.json` описан как «массив объектов» без полей; фактический формат — `simcore/viz.export_trace` (`name`, `step_s`, `n_robots`, `n_chargers`, `layout`, `frames`, `summary`…) | Плеер 07a (spike 2D) пишется строго по формату трасс — без схемы его не проверить генерацией типов | Тип и проверка формата написаны вручную по `export_trace` (`src/api/mappers/trace.ts`); трассы для моков пишет сам движок (`npm run gen:traces`) | open |
| 7 | **Названия вердиктов.** В API симуляции `needs_additions` и `not_achievable`, в PRD 11.4 — «нужно докупить» и «недостижимо» (`need_more`, `unreachable` у фронта) | Нет — только чтобы не путаться в переписке | Маппер переводит явно (`src/api/mappers/simulation.ts`) | answered |
| 8 | **Окупаемость, когда эффект ≤ 0.** `CalcResult.paybackYears = null` — «не окупается». Можно ли сохранить оценку с таким сценарием и что тогда в снимке (PRD 11.5, открытый вопрос)? | Снимок результата требует число окупаемости | Мок не даёт сохранить сценарий без окупаемости (`ConflictError`) | open |
| 9 | **Id сущностей.** В API — UUID, у фронта шаблонные типы (`PJ-…`, `LOC-…`, `LP-…`) по демо-данным | При подключении API шаблоны id станут неверными | Мапперы передают id как есть; шаблонные типы id заменим на строки при подключении | open |
